# Windows 无感定时预约设计

## 目标

让 Windows 在三个预约窗口内自动唤醒电脑并运行一次预约任务。Python 不常驻后台，浏览器不显示窗口、不抢占桌面；每个账号每次只处理一个指定学习时段。

## 默认时间

| 任务 | 时间 | 预约日期 | 学习时段 |
|---|---:|---|---|
| `SeatAssistant-Morning` | 前一天 22:05 | 次日 | `morning` |
| `SeatAssistant-Afternoon` | 当天 12:30 | 当天 | `afternoon` |
| `SeatAssistant-Evening` | 当天 19:10 | 当天 | `evening` |

第一段默认使用 22:05，避开 19:30 开放预约后的高峰；安装脚本允许用 `-MorningAt "22:05"` 覆盖。每个任务在窗口内按 10 分钟间隔重复触发，代码仍会二次检查安全窗口。

## 执行链路

1. Windows 计划任务使用 `WakeToRun`、`StartWhenAvailable`、隐藏执行和 `IgnoreNew` 并发策略。
2. 任务启动 `python -m scripts.run_scheduled_task --period <period>`，入口只运行一次后退出。
3. 入口根据当前时间计算当天或次日目标日期；任务错过安全窗口时直接退出，不把预约日期顺延到错误日期。
4. 入口加载全部启用账号，按账号配置顺序串行调用调度器。
5. 调度器仅处理本次任务对应的时段，读取本地记录和“我的预约”接口；已有预约、未初始化、结果不明确和页面异常都遵循现有安全规则。
6. 预约流程使用 `LockedBrowser(headless=True)`，账号锁仍然有效，成功或异常后关闭浏览器并退出进程。
7. 运行日志写入 `logs/scheduled-YYYY-MM-DD.log`，目录不进入 Git。

## 电脑状态边界

- 锁屏或睡眠：在 Windows 电源策略允许唤醒时可以执行。
- 必须保持 Windows 用户会话有效；使用 `InteractiveToken`，不支持用户已注销时无人登录运行。
- 关机、注销、断网或设备不支持唤醒时无法预约。
- 由于浏览器为无头模式，执行不会弹出窗口或覆盖用户当前桌面。

## 安全边界

- 每个任务只提交一个学习时段，不会因为重复触发自动推进到另一个时段。
- 预约成功、失败或结果不明确写入独立账号数据库，并通过已有通知层报告。
- 重复启动由 Windows 的 `IgnoreNew` 和账号锁双重阻止。
- 任务安装脚本会移除旧的 `SeatAssistant` 登录启动常驻任务，避免两套调度器同时运行。

## 验证

- 测试目标日期：上午任务映射次日，下午/晚上任务映射当天，窗口外安全跳过。
- 测试目标时段：指定下午任务不会跳到晚上任务。
- 测试浏览器：计划任务路径传入 `headless=True`。
- PowerShell 安装脚本完成语法解析检查。
- 完整测试当前为 `289 passed`。

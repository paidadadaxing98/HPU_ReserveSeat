# 企业微信智能机器人长连接设计

**目标**：让本地程序以企业微信智能机器人长连接方式接收消息，并按命令把推文一对一发送给指定用户。

## 范围

- 使用企业微信智能机器人 API 模式的 WebSocket 长连接。
- 支持 `Bot ID + Secret` 鉴权、心跳保活、断线重连和指数退避。
- 支持消息去重，避免重连或重复投递导致同一条命令被执行多次。
- 支持命令路由，把不同文本消息分发到不同处理器。
- 支持单实例保护，避免同一台机器上同时跑两个机器人进程。
- 支持一对一发送推文给指定用户，发送内容以文本或 markdown 形式输出。
- 不替换现有预约、Webhook 通知和 Windows 定时任务入口。

## 输入与输出

### 输入消息

机器人只处理文本类命令，默认命令格式为：

```text
推文 @account03 标题 | 链接
推文 account03 标题 | 链接
推文 account03 标题 | 链接 | 备注
```

其中第一个字段是命令，第二个字段是目标账号或别名，后续字段组成推文正文。正文至少包含标题和链接，分隔符优先使用 `|`。

### 输出消息

- 成功时向指定企业微信用户一对一发送推文内容。
- 失败时向发起者返回可读的错误说明。
- 去重命中的消息不重复回复，只记录为已处理。

## 配置

新增机器人配置项，优先从环境变量读取：

- `SEAT_WECOM_BOT_ID`
- `SEAT_WECOM_BOT_SECRET`
- `SEAT_WECOM_BOT_WS_URL`
- `SEAT_WECOM_BOT_DEFAULT_USER`
- `SEAT_WECOM_BOT_LOCK_FILE`

账号级配置继续由 `accounts.json` 提供，新增一对一接收人映射字段：

- `wecom_user_id`：该账号默认接收推文的企业微信用户 ID
- `wecom_aliases`：可选别名列表，用于命令路由

## 结构

```text
scripts.run_wecom_bot
    -> WeComBotRunner
    -> WebSocket transport
    -> MessageDeduplicator
    -> CommandRouter
    -> WeComPushService
    -> account resolver / sender
```

`WeComBotRunner` 只负责循环、重连和退出控制。命令解析与业务处理都放在独立组件里，方便测试和替换传输层。

## 安全边界

- 机器人进程只允许一个实例运行。
- 重连后继续使用同一套业务路由，但不会重复处理已见过的消息 ID。
- 发送失败不会中断接收循环。
- 当前消息优先通过回调 `response_url` 回复发起人；跨用户主动推送需要企业微信侧开放对应发送能力。
- 未配置 `Bot ID` 或 `Secret` 时，机器人直接退出，不影响预约功能。
- 现有 webhook 通知继续保留，不和长连接共用实现。

## 测试

- 命令解析覆盖合法输入、缺少正文、缺少目标账号和非法格式。
- 路由测试覆盖别名映射、默认接收人和未知账号。
- 去重测试覆盖首次处理、重复消息和缓存过期。
- 重连测试覆盖异常断开、退避延迟和恢复后继续收消息。
- 单实例测试覆盖锁文件已占用时安全退出。
- 一对一发送测试覆盖 payload 渲染和发送失败回退。
